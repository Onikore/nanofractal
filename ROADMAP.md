# Roadmap

Рабочий план развития nanofractal после 0.6.1. Задачи идут по убыванию
«польза / усилия»; релизы собирают их в группы. Отмечаем `[x]` по мере
выполнения, в PR/коммите ссылаемся на номер задачи (например `R2`).

## Правила для каждой задачи

1. **Скорость меряем, не угадываем:** `benchmarks/fractal_bench.py run --vs base.json`
   (1 ядро: `--threads 1`, все ядра: `--threads 0`), сравнение до/после в описании.
2. **Качество не ухудшаем:** `benchmarks/robustness.py --json` до и после,
   разница — в описании. Изменение поведения допустимо только осознанно и с
   записью в CHANGELOG.
3. **Точность углов внешних маркеров остаётся бит-в-бит** с эталоном
   (`tests/test_reference_equivalence.py`), если задача явно не меняет
   алгоритм — тогда эталонный тест обновляется вместе с обоснованием.
4. Перед пушем: `pre-commit run --all-files`, полный `pytest`, при изменении C++ —
   прогон под ASan (`-DNF_SANITIZE=ON`), сборка под OpenCV 4.10 и 5.
5. Новый функционал — с примером в `guide/` (его выполнит `tests/test_guide.py`)
   и строкой в CHANGELOG.

## Релиз 0.6.2 — доступность и поза «бесплатно»

### R1. Колёса для macOS (arm64 + x86_64)
- [ ] Добавить macOS в матрицу `release.yml` (`macos-14` arm64, `macos-13` x86_64).
- [ ] Статическая минимальная OpenCV для macOS (адаптировать `ci/build-opencv.sh`,
      без `-march`, для x86_64 — `NF_MARCH=x86-64-v3`).
- [ ] `delocate` для упаковки, тесты колеса в cibuildwheel.

**Готово, когда:** `pip install nanofractal` на Mac ставит колесо, тесты колеса
зелёные в CI, README/guide упоминают macOS.

### R2. Поза по всем видимым уровням без inner points
Сейчас без `with_inner_points` поза — по 4 углам одного маркера.
- [ ] `estimate_pose`: при отсутствии inner points использовать углы **всех**
      найденных уровней (их 3D-координаты известны из конфигурации), решатель
      `SOLVEPNP_IPPE` (при одном уровне — как сейчас, `IPPE_SQUARE`).
- [ ] Сценарий в `robustness.py`: ошибка позы (вращение/перенос против
      ground truth) для `detect` vs `detect(with_inner_points=True)`.

**Готово, когда:** ошибка позы в режиме `detect` заметно ниже прежней,
стоимость `detect` не изменилась, тесты позы обновлены.

### R3. `detection_scale` без ловушки нецелых коэффициентов
Сейчас 0.75 и 0.35 медленнее, чем без масштаба (быстрый `INTER_AREA` только
для целых коэффициентов уменьшения).
- [ ] Вариант А (минимальный): нецелые значения округлять к ближайшему
      быстрому (0.5 / 0.25), предупреждение в документации.
- [ ] Вариант Б: уменьшение ×2 быстрым путём + доуменьшение `INTER_LINEAR`.
- [ ] Выбрать по замеру скорости и `robustness.py`, задокументировать в `guide/05`.

**Готово, когда:** любое значение `detection_scale < 1` не медленнее полного
разрешения; изменение поведения записано в CHANGELOG.

### R11a. CI
- [ ] Колёса для Python 3.14.
- [ ] Job `ci` под OpenCV 5 (сейчас только системная 4.6).

## Релиз 0.7.0 — скорость на ARM, в inner-режиме и трекере

### R4. NEON для aarch64
Raspberry Pi / Jetson — основная платформа для маркеров; сейчас там
скалярные пути поиска стартов контуров и сравнения порога.
- [ ] NEON-версии `collect_starts` и сравнения в `AdaptiveThreshold`
      (или OpenCV universal intrinsics, чтобы один код покрыл SSE/AVX2/NEON).
- [ ] Эквивалентность: `tests/test_reference_equivalence.py` на aarch64 (CI под QEMU).
- [ ] Замер на реальной плате (Raspberry Pi 5 / Jetson), цифры в `guide/05`.

**Готово, когда:** ×1.5+ на ARM при бит-в-бит результатах.

### R5. Inner points без FAST
Положения внутренних углов уже предсказаны гомографией от найденных уровней.
- [ ] Прототип: `cornerSubPix` прямо из предсказанных точек, фильтр по
      контрасту/классу угла вместо FAST + kfilter + поиска соседей.
- [ ] Сравнить с текущим путём: число точек, ошибка репроекции, ошибка позы
      (`robustness.py`), скорость.

**Готово, когда:** inner-режим ≥ 1.5× быстрее (цель: 1080p ~1.2 мс на всех
ядрах против ~2.3) без ухудшения ошибки позы.

### R6. Масштаб в трекере без потери точности
Эксперимент: масштаб по предыдущему кадру даёт ×4.6 на 4K, но ошибка углов
0.39 → 1.3 px (cornerSubPix стартует слишком далеко).
- [ ] Уточнение углов coarse-to-fine по пирамиде (как в Romero-Ramirez 2018).
- [ ] Опция `FractalTracker(auto_scale=True)`.
- [ ] Замер на синтетическом видео (`build/scratch/exp_video.py` → перенести в
      `benchmarks/`): скорость и ошибка углов против ground truth.

**Готово, когда:** ×3+ на 4K, ошибка углов ≤ 0.45 px.

### R7. Порог на 4K
4.7 мс на одном ядре — самая дорогая стадия на 4K.
- [ ] Тайлы по строкам + слияние с масками соседей в одном проходе.

**Готово, когда:** −30% времени порога на 4K, бит-в-бит.

## Релиз 0.8.0 — несколько маркеров и реальные данные

### R8. Несколько маркеров одной конфигурации в кадре
Сейчас каждый уровень (id) возвращается один раз — два одинаковых маркера
не различить.
- [ ] Группировка уровней в экземпляры по вложенности (уровень k+1 внутри
      квадрата уровня k), без дедупликации по id между экземплярами.
- [ ] API: `DetectionResult.instance` (номер экземпляра на каждую строку) или
      список результатов; `estimate_pose` по экземпляру.
- [ ] Обратная совместимость: поведение по умолчанию для одного маркера то же.

**Готово, когда:** кадр с 3 одинаковыми маркерами даёт 3 экземпляра и 3 позы.

### R9. Набор реальных снимков
Вся валидация сейчас синтетическая.
- [ ] 50–100 фото (телефон + машинная камера): дистанции, наклоны, блики,
      окклюзия, движение; шахматка рядом с маркером для ground-truth позы.
- [ ] `benchmarks/real_images/manifest.json`, метрики: доля найденных уровней,
      ошибка позы.
- [ ] Хранить вне пакета (git LFS или релизный артефакт), в CI — по желанию.

**Готово, когда:** `robustness.py --real-dir` выдаёт таблицу по реальным данным.

### R10. Устойчивость к окклюзии
- [ ] Чтение бит по периметру ячейки (идея из Recursive ArUco, 2026) как опция.
- [ ] Детекция внешнего уровня при 3 видимых углах с опорой на внутренние уровни.
- [ ] Сценарий окклюзии в `robustness.py`, проверка на наборе R9.

**Готово, когда:** доля обнаружения при 20–30% окклюзии выше текущей, без
регрессий на остальных сценариях.
